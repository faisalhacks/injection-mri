Tools (project pages opened):
- Neuronpedia, https://www.neuronpedia.org/. Search runs custom text through a model to find top-matching latents (residual stream, all layers). Steer lets you modify activations with latents or custom vectors. Graph traces reasoning on custom prompts. Supports Gemma, Qwen3, Llama 3.x, GPT-OSS and others. This is the closest existing "scan a prompt" view. It surfaces SAE latents, not an injection-specific detector.
- TransformerLens, https://github.com/TransformerLensOrg/TransformerLens. Activation caching and hooks that edit or remove activations. No built-in prompt-scanning visualisation was described on the page.
- TaskTracker (from #3) ships a dataset and toolkit but its abstract describes no interactive per-token view.

I did not find an existing per-layer, per-token "injection MRI" viewer. That is an absence of evidence from a limited search, not proof.

## 2. What is already known

1. Injection-following is linearly readable from hidden states before any output is generated (#2, #3, #4). This holds across many models, including held-out attacks.
2. A residual-stream direction for "followed vs resisted the injection" can be fitted by difference-in-means, and subtracting it from the data tokens at prefill reduces injection-following, with a reversed-polarity test and random-direction controls (#1). This covers our core claim of a causal, ablatable direction. It was published 29 Sep 2026.
3. Detection and steering are not the same thing. CounterSteer reports two directions that separated attacks but did not steer. A probe can be a valid detector and a useless intervention, so a good per-layer probe curve does not by itself license an ablation claim.
4. Probe AUROC is easy to inflate. Position and length alone reach 0.91-0.98 (#7), and a 0.998 AUC may not mean semantic detection (#8). Untrained random-direction probes sit at 0.46-0.59 AUROC (#2), which is a useful floor.
5. The best layer is model-specific and sometimes very early (layer 2/32 on one model in #2), so a layer sweep is required (#2).
6. Attention-based detection is a strong, training-free baseline, and it separates successful injections better than probes do on at least two models (#5, #6).
7. A single "refusal-like" direction is a simplification. Multiple directions or cones can mediate the same behaviour (#10).
8. Read-only decisions at prompt positions can be hard: CounterSteer reports linear probes at its prompt sites near chance for the attacker-argument decision, with signal appearing only at value emission (AUC 0.824-0.903). That is a different decision from "instruction followed", and a different setup from #2/#3, so the disagreement is unresolved rather than a contradiction.

## 3. What our project could add that is not already done

Blunt version: **the core idea, "find a residual-stream direction for following an injected instruction, probe it per layer, ablate it, reduce injection-following", is a replication of CounterSteer (#1) plus #2 and #3. It is not novel.** We must not claim to have discovered or been first to show a causally ablatable, pre-generation-detectable injection direction. Those claims are taken.

What may still be open, in rough order of honesty:

- **A small-model, reproducible, cheap replication.** CounterSteer uses 8B to 106B models. A replication on one small chat model with released code, run on BIPIA, InjecAgent and TaskTracker, is a legitimate contribution if described as a replication. It adds independent evidence for a single-source result (I found no independent replication of #1).
- **Direct detection-versus-intervention comparison at the same layers.** Per-layer probe AUROC next to per-layer ablation effect, on one model and one benchmark. #1 says these dissociate; showing the curves would be a useful, checkable result. We would have to check how much of this #1 already shows before claiming it.
- **Controls from #7 and #8 applied to the data-vs-instruction direction**, meaning matched negatives, position and length baselines, random-direction controls, and successful vs unsuccessful splits (#6). Several of these papers criticise probe evaluations; few combine those controls with an ablation test.
- **Multi-direction analysis** in the spirit of #10 (is one direction enough, does a second direction add anything). Untested for injections as far as I found.
- **The interactive per-layer, per-token viewer itself.** I found no injection-specific one, though Neuronpedia gives generic custom-text latent search and steering. The tool is a product contribution, not a scientific finding, and should be described as such.
- **Detect-then-ablate gating** (ablate only when the probe fires), to recover utility. #2 gates a prompt prefix, and #1 is always-on. Gating the ablation itself did not appear in what I read. Unverified beyond the abstracts and the HTML I opened; check before claiming it.

Things that would be overclaiming: "first", "novel direction", "pre-generation detection is new", "causal evidence" without random-direction and add-the-direction controls, and any AUROC without the shortcut controls.

## 4. Method recommendations from the literature

1. **Direction recipe: difference-in-means on followed vs resisted episodes, per layer** (#1, #9). Pair episodes that differ only in whether an embedded instruction is followed. Prefer diff-in-means over probe weights for the intervention direction (#1 states this preference). Pool over the payload span. Also test the contrastive pair "injection present vs absent" separately, since #6 shows these separate different cases.
2. **Layers and token positions.** Sweep all layers. Do not assume mid-depth; #2 selected layer 2/32 for one model and 38/78 for another, chosen on held-out AUROC. For detection, read the post-assistant token during prefill (#2) and/or the activation delta around the data (#3). For intervention, edit tool-result or data tokens during prefill only (#1). Record both the probe site and the steering site; #1 probes pre-MLP and steers block output.
3. **Causal protocol.** Run both arms: subtract the direction (following should fall) and add it (following should rise), with matched random directions and a utility guard (#1). Keep the direction only if it passes. Report utility on benign tasks alongside attack reduction, because #1 reports a 93-100% benign-utility range and larger costs when the model must reason over steered content.
4. **Baselines.** Attention Tracker (#5, training-free) and the TaskTracker activation-delta probe (#3) for detection. For defence, spotlighting or delimiters, prompt sandwich or reminder, and BIPIA's boundary-awareness and reminder defences (#13), plus a classifier filter. Include untrained random-direction probes as the floor (#2) and position-plus-length-only as the shortcut floor (#7).
5. **Benchmarks and metrics.** BIPIA for text tasks (#13), InjecAgent (#14) and AgentDojo (#15) for agents. Add TaskTracker (#3) for detection and SEP (#17) for data-vs-instruction separation. Metrics used by others: AUROC for detection (#2, #3, #5, #6); attack success rate and compromise rate for defence (#1, #2); benign utility. Split results into successful and unsuccessful injections (#6), and report held-out attack and held-out task-suite generalisation, since #2 and #1 both do. Use matched negatives in training (#7).

## B. What is replication and what is new

**Replication (not novel):**
- The diff-in-means refusal direction, its ablation and its addition (R1). We run it as the strong baseline.
- The idea that a few percent of neurons (R2) or a handful of attention heads (R4) carry safety behaviour, and that patching or ablating them changes it. We re-find culprit sets with a different procedure (attribution patching with exact-patch validation), on Qwen2.5 models; this is a replication of the finding type on new models, not a new finding.
- Mitigating false refusal with an activation-space intervention (R5). Our over-refusal arm is a unit-level variant of R5; R5 works with a single direction.
- Attribution patching as a fast approximation to patching (R6-R8). We use the plain linear version, then validate on the top 200 by exact patching, in the AtP* "pre-filter then verify" spirit but without the AtP* corrections.

**What I believe is new, to be checked, not claimed:**
1. Both neuron AND head granularity, in both directions (jailbreak bypass and over-refusal) on one pipeline, with one set of controls. R2 does neurons, R4 does heads, R5 does a direction; I did not find a paper that does all in one comparison. Absence of evidence from a limited search.
2. Causal verification against matched controls on held-out behaviours AND held-out wrapper templates: same-layer random units, a non-causal activation-difference top-k, and the Arditi direction. How R2/R4 controlled this was not read in full text.
3. Side-effect checks in the same harness (harmless refusal, unsafe-contrast compliance, MMLU).
4. **Family analysis (H5/H6, pre-registered):** whether different in-the-wild jailbreak strategy families (using the dataset's own community labels) are mediated by the same units, and whether transfer of culprits across families, platforms and dates holds. I did not find prior work on this question; again limited search.
5. A one-command report and demo tool. A product contribution, not a finding.

Overclaiming to avoid: "first to find safety neurons/heads", "first to fix over-refusal with steering", "causal" without controls, and any statement that a culprit "is the safety neuron" (interpretation sections are observations only).
